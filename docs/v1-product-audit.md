# 第一代产品阶段审查

## 当前目标

把 Codex 灵兽桌宠从 demo 推进到第一代产品闭环。第一代不追求完整商业化，而是证明核心体验成立：

- 能读取 Codex 短期/长期用量。
- 能把用量翻译成灵兽状态。
- 能投喂文件并生成投喂玉简。
- 能把有效产出计入成长，而不是鼓励无意义消耗 token。
- 能清楚说明隐私边界。

## 从相似项目吸收的改进

### Codex 用量小窗类

吸收点：

- 用量展示必须清晰直接。
- 短期窗口和长期窗口要分开。
- 重置时间要显示。
- 读取失败时要明确降级为 demo / fallback，而不是假装成功。

已落地：

- `codex_usage.py` 抽出真实 Codex 用量读取模块。
- 浏览器 demo 和桌面窗共用同一数据来源。
- 页面显示短期灵脉、长期灵脉和回转时间。

### AI 桌宠类

吸收点：

- 宠物要有状态反馈，不只是图标。
- 成长应该和用户行为有关。
- 小窗/mini 模式很重要。
- 装扮和阶段进化适合后续扩展。

已落地：

- 桌面悬浮窗 `desktop_pet.py`。
- 像素饕餮状态随用量变化。
- 浏览器 demo 有开灵、投喂、饱腹、消化率、境界。
- 预留头部、胸颈、背部装扮插槽方向。

### Git / 项目进度桌宠类

吸收点：

- 不只看 AI 用量，还要看项目进展。
- commit、push、测试等工程动作可以成为成长事件。

已落地：

- 世界观已定义：commit 是玉简，push 是上交宗门，测试是渡劫。
- 第一代界面加入“一代闭环”面板，强调有效创作而不是烧 token。

## 第一代闭环验收标准

页面中新增“一代闭环”面板，按 4 项判断当前产品是否进入可用闭环：

1. 真实灵脉同步：是否读取到真实 Codex 用量。
2. 灵材投喂：是否投喂过文件。
3. 有效炼化：是否有用户确认的有效成果。
4. 玉简入洞府：是否把投喂记录本地保存到项目。

这四项是第一代产品的方向守护：

- 不只做漂亮宠物。
- 不只做 token 仪表盘。
- 不鼓励无意义消耗。
- 不牺牲隐私。

## 互动反馈修正

用户反馈第一版桌宠“互动反馈太少、不够生动、无法投喂、没有炼化显示、视觉效果差”。本次修正：

- 文件选择框改为绑定桌宠父窗口，并在打开时临时取消置顶，避免被桌宠挡住。
- 新增对话气泡，反馈点击、投喂、取消投喂、炼化成功等动作。
- 新增炼化炉进度条，投喂后显示炼化进度，炼化成功时进入满值发光状态。
- 新增灵兽日志，记录最近交互事件。
- 扩大像素舞台，加入光环、粒子、背包、额饰、尾巴、肚中灵气、投喂物下落等视觉反馈。

## UI / 美术打磨

继续优化桌面版的产品感：

- 顶部增加产品识别文字和阶段徽章。
- 增加境界、玉简、炼化三个状态小牌，减少“调试窗”感觉。
- 将系统默认进度条替换为自绘像素灵脉条。

## Bongo Cat 路线校正

产品方向校正为“程序化桌宠的生命感”：

- 不先追求精美立绘，先追求输入驱动的小动作。
- Codex 使用、文件投喂、鼠标点击、键盘输入都应触发灵兽动作。
- 保持程序绘制简化角色、小而稳定的动作循环、置顶桌面层。

已落地：

- 新增“敲玉简”动作。
- 窗口获得焦点后，键盘输入会触发左右爪敲击动画。
- 鼠标点击会让窗口获得键盘焦点，便于测试输入驱动动画。
- 新增可开关的全局输入感应：默认关闭，开启后感应键盘/鼠标输入发生，但不记录具体内容。

## 常驻桌宠体验

继续沿 Bongo Cat 路线推进，把桌面版从“大控制面板”压缩成更适合常驻的小生命：

- 新增迷你桌宠模式：右上角按钮可收起详细面板，只保留灵兽主体、灵脉提示、状态小牌和气泡。
- 新增空闲打坐/犯困状态：长时间没有互动时，饕餮会闭眼并出现睡眠符号。
- 任意有效互动都会唤醒灵兽，包括点击、窗口内键盘输入、全局输入感应、投喂文件和炼化确认。
- 迷你模式仍保持置顶和轻微透明，便于之后包装成真正的透明/置顶桌面层。

## 生命状态机强化

本轮继续强化“程序化生命感”，避免所有互动都像同一种动画：

- 将桌面宠物动作整理为清晰状态：待机呼吸、敲玉简、被摸醒、吞灵材、炼化中、发光开心、灵脉偏低、打坐犯困。
- 敲玉简加入左右爪下落、身体轻微晃动、敲击火花和“哒”字反馈。
- 投喂后先进入吞灵材状态，再进入短暂炼化循环，肚中灵气会跳动并冒出小粒子。
- 迷你模式进一步减少文字和控制区，只保留更适合常驻的灵兽主体与简短状态气泡。
- 全局输入感应继续只记录“输入发生”，不记录按键内容。
