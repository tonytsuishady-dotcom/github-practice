# 第一代产品阶段审查

## 当前目标

把 Codex 灵兽桌宠从 demo 推进到第一代产品闭环。第一代不追求完整商业化，而是证明核心体验成立：

- 能读取 Codex 短期/长期用量。
- 能把用量翻译成灵兽状态。
- 能投喂文件并生成投喂玉简。
- 能把有效产出计入成长，而不是鼓励无意义消耗 token。
- 能清楚说明隐私边界。

## 从相似项目吸收的改进

### Codex 用量小窗类

吸收点：

- 用量展示必须清晰直接。
- 短期窗口和长期窗口要分开。
- 重置时间要显示。
- 读取失败时要明确降级为 demo / fallback，而不是假装成功。

已落地：

- `codex_usage.py` 抽出真实 Codex 用量读取模块。
- 浏览器 demo 和桌面窗共用同一数据来源。
- 页面显示短期灵脉、长期灵脉和回转时间。

### AI 桌宠类

吸收点：

- 宠物要有状态反馈，不只是图标。
- 成长应该和用户行为有关。
- 小窗/mini 模式很重要。
- 装扮和阶段进化适合后续扩展。

已落地：

- 桌面悬浮窗 `desktop_pet.py`。
- 像素饕餮状态随用量变化。
- 浏览器 demo 有开灵、投喂、饱腹、消化率、境界。
- 预留头部、胸颈、背部装扮插槽方向。

### Git / 项目进度桌宠类

吸收点：

- 不只看 AI 用量，还要看项目进展。
- commit、push、测试等工程动作可以成为成长事件。

已落地：

- 世界观已定义：commit 是玉简，push 是上交宗门，测试是渡劫。
- 第一代界面加入“一代闭环”面板，强调有效创作而不是烧 token。

## 第一代闭环验收标准

页面中新增“一代闭环”面板，按 4 项判断当前产品是否进入可用闭环：

1. 真实灵脉同步：是否读取到真实 Codex 用量。
2. 灵材投喂：是否投喂过文件。
3. 有效炼化：是否有用户确认的有效成果。
4. 玉简入洞府：是否把投喂记录本地保存到项目。

这四项是第一代产品的方向守护：

- 不只做漂亮宠物。
- 不只做 token 仪表盘。
- 不鼓励无意义消耗。
- 不牺牲隐私。
